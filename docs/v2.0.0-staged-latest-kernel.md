# v2.0.0 最新内核稳定灰度

## 目标

`v2.0.0` 同时满足三个目标：

1. 日常仍使用 `claude`，不增加新的用户入口。
2. 下一次官方启动使用经过验包的 `2.1.220` 内核。
3. 保留 `2.1.170` 的旧 profile、session、原包和二进位作为可复现回退。

当前已经运行的进程不会被替换或终止。版本切换只作用于下一次启动。

## 行为变化

### 官方通道

- 使用配置中的版本化 `config_dir`，而不是写死 `~/.claude-official`。
- 新 profile 只迁移已审核的 settings、`CLAUDE.md` 和自定义 agents。
- 不迁移旧 session、history、plugin、marketplace、缓存或本地账号状态文件。
- `require_unpinned_model=true` 时，settings 中不能固定 `model`。
- 出口 IP 不在白名单时直接退出，不再接受 `unsafe`。
- background agents、cron、Remote Control、workflows、hooks 和自动更新继续关闭。

这意味着旧会话不会出现在新 profile 的 `/resume` 列表。需要延续旧任务时，应在
旧 `2.1.170` 环境完成，或整理摘要后在新版建立新会话。

### CC Switch 通道

- Claude Code 客户端继续固定版本、SHA-256 和 Anthropic Team ID。
- 15721 必须由配置指定的 CC Switch 执行文件唯一监听。
- macOS 同时固定 CC Switch Team ID、Bundle ID 和应用版本。
- 使用无模型请求的 `OPTIONS /v1/messages` 探针验证协议行为。

这些检查只证明本机 compatibility endpoint 身份，不把它描述成 Anthropic
官方模型通道。

## 使用影响

- 日常命令不变：官方用 `claude`，CC Switch 用 `claude-cc`。
- 启动检查仍需要几秒。
- 未授权 IP、错误 TLS、错误 endpoint 或程序身份不匹配时无法强行继续。
- 新官方 profile 第一次打开时可能需要完成客户端初始化或官方登录确认。
- 旧会话和旧插件不会自动出现在新 profile。
- CC Switch 应用升级后，版本固定会主动阻止启动，需重新核验后更新配置。
- 运行中的 `2.1.170` 会话不会受到影响。

## 本机验包记录要求

每个客户端版本目录至少保留：

```text
claude
manifest.json
npm-dist.json
原始 npm tarball
```

`manifest.json` 应记录客户端 SHA-256、tarball SHA-256、npm shasum、npm
integrity、npm 签名元数据、macOS identifier、Team ID 和验证时间。

仓库不提交大型二进位、真实 IP、账号信息、OAuth 数据或本机配置。

## 灰度与回退

建议先运行 3 至 5 个新的前台会话，观察 24 至 48 小时：

- API retry 是否明显增加。
- TUI、权限和工具调用是否出现异常。
- 进程 RSS 是否持续膨胀。
- 终端退出后是否存在残留进程。
- 实际出口、TLS issuer 和 endpoint 是否保持一致。

出现异常时，不在运行中自动切版本或 kill。结束当前会话后，将官方安全配置中的
`command`、`client_version`、`client_sha256` 和 `config_dir` 恢复到
`2.1.170` 基线，再执行 `claude --precheck-only`。

本机可以预先保存两个不含凭据的完整配置快照：

```text
~/.claude-guard/version-pins/official-2.1.220.json
~/.claude-guard/version-pins/official-2.1.170.json
```

回退时复制经过预检的 `2.1.170` 快照覆盖安全配置即可；不要移动或删除正在运行
会话使用的 profile。

## 验收

```bash
./scripts/check.sh
python3 scripts/verify-terminal-exit.py
CLAUDE_GUARD_ASSUME_YES=1 claude --precheck-only
claude-cc --precheck-only
```

上述检查不提交模型 prompt。
