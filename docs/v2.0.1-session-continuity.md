# v2.0.1 Session 连续性修正

## 结论

Claude Code 升级默认应延续已经稳定使用的官方 profile。`v2.0.1` 只替换经过
验包的客户端内核，不要求切断 settings、登录状态或 session 历史。

官方 Claude Code 将 session 作为本机持续保存的工作上下文，并正式支持
`--continue`、`--resume` 和 `/resume`。新建空 session 不是账号安全要求，
恢复旧 session 也不是已知的封禁因素。

## 默认结构

```text
claude
  -> claude-guard 2.0.1
  -> reviewed Claude Code 2.1.220
  -> existing ~/.claude-official
  -> existing settings and sessions
  -> guarded HTTP CONNECT route
  -> api.anthropic.com
```

保持不变：

- 日常入口仍是 `claude`。
- 原官方 profile、OAuth 状态、CLAUDE.md、agents、settings 和 session。
- 原模型设置；用户可在会话中自行切换模型。
- IP、TLS、IPv6、客户端签章、生命周期和项目设置门禁。
- `2.1.170` 回退客户端和旧 session。

发生变化：

- 下一次启动使用固定、验包的 `2.1.220` 客户端。
- `unsafe` 网络绕过仍然禁用。
- CC Switch 继续使用独立 `claude-cc` 路由。

## 使用影响

- `/resume` 仍会显示原工作目录下的旧 session。
- `claude --continue` 会继续当前目录最近一次对话。
- 已经运行的旧版本进程不受配置指针变化影响。
- 新客户端若在某个新目录首次启动，仍可能询问 workspace trust；这与 session
  版本无关。
- 不应同时在两个终端恢复同一个 session；如需并行，应使用 `--fork-session`。

## 可选隔离

只有在定位配置、插件或 session 损坏问题时，才临时使用版本化空 profile。
排障完成后恢复稳定 profile，不复制或重写原 transcript。

## 无模型验证

发布前验证：

1. `claude --precheck-only` 通过。
2. `2.1.220` 使用原 `CLAUDE_CONFIG_DIR` 启动。
3. `claude --resume` 能读取旧 session 列表。
4. 退出选择器，不选择 session、不提交 prompt。
5. 现有旧版本进程持续运行。
