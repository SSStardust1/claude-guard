# Claude 守护 v0.2.1 指纹 Tripwire 说明

更新时间：2026-07-01

## 目标

`v0.2.1` 增加 Claude Code 客户端指纹预检，用于识别已知 date/time watermark 逻辑和会激活该逻辑的本地条件。

这个功能的目标是降低误伤风险，而不是规避服务端风控。它不会转发、修改、清洗、解包或重写 Claude Code 的请求。

## 不做什么

本版本明确不做以下事情：

- 不做 TLS MITM。
- 不改 `ANTHROPIC_BASE_URL`。
- 不运行本地 API 反代。
- 不修改 Claude Code 请求体。
- 不 patch Claude Code 二进制。
- 不伪造 timezone、locale、系统时间或账号地理画像。

这些方式会把官方链路变成非官方链路，增加账号风险。

## 做什么

启动前检查原始 Claude Code 客户端文件是否同时包含以下已知特征：

- `Asia/Shanghai` 或 `Asia/Urumqi`。
- date/time watermark 相关字符串，例如 `Today...date is`、`\u02BC`、`\u02B9` 或日期格式改写逻辑。

如果客户端不包含这些特征，直接通过。

如果客户端包含这些特征，则继续检查当前环境是否存在激活条件：

- 当前 shell 中存在 `ANTHROPIC_BASE_URL`。
- 本机 timezone 是 `Asia/Shanghai` 或 `Asia/Urumqi`。

默认模式是：

```bash
CLAUDE_GUARD_FINGERPRINT_MODE=fail-active
```

在默认模式下，只有“客户端含已知逻辑”和“激活条件存在”同时成立时才拒绝启动。

## 模式

```bash
CLAUDE_GUARD_FINGERPRINT_MODE=off
CLAUDE_GUARD_FINGERPRINT_MODE=warn
CLAUDE_GUARD_FINGERPRINT_MODE=fail-active
CLAUDE_GUARD_FINGERPRINT_MODE=strict
```

- `off`：关闭检查。
- `warn`：只警告，不阻断。
- `fail-active`：默认模式，只在存在激活条件时阻断。
- `strict`：只要客户端包含已知逻辑就阻断。

## 旧 Profile 检查

`v0.2.1` 还会检查默认 profile：

```text
~/.claude/settings.json
```

如果其中仍有旧 CC Switch / base URL 残留，默认只警告，不阻断：

```bash
CLAUDE_GUARD_LEGACY_PROFILE_MODE=warn
```

原因是官方入口实际使用：

```bash
CLAUDE_CONFIG_DIR="$HOME/.claude-official"
--setting-sources=
--settings "$HOME/.claude-official/settings.json"
```

因此默认 profile 的残留不会被官方入口读取。但保留警告可以提醒用户：默认 profile 仍是污染源，不能直接运行原始 `claude`。

## 示例核查结果

以下是脱敏示例，用于说明预期输出形态：

- 原始 Claude Code CLI：`2.1.68`。
- 原始命令：`/usr/local/bin/claude`。
- 官方 profile：`~/.claude-official/settings.json` 未发现 `ANTHROPIC_BASE_URL`、`apiKeyHelper`、`PROXY_MANAGED` 等标记。
- 默认 profile：`~/.claude/settings.json` 仍包含旧 `127.0.0.1:15721` / `PROXY_MANAGED`，按 warn 模式提示。
- 本机 timezone：`Asia/Singapore`。
- 当前 `2.1.68` 客户端未发现 `Asia/Shanghai` / `Asia/Urumqi` watermark 特征。

结论：当前官方 guard 入口没有发现会激活已知 watermark 的条件。
