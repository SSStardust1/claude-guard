# v0.2.4 生命周期加固

## 目标

`v0.2.4` 解决的是一个具体风险：用户关闭终端后，Claude Code 的 background agent、supervisor、Remote Control、动态工作流、hook 或第三方插件仍可能继续运行。

本版本采用保守策略：在尚未部署并验证官方 `processWrapper` 之前，官方 profile 只允许受守护的前台会话。

## 官方支持的控制面

本版本仅使用 Claude Code 公开支持的环境变量与 settings：

- `disableAgentView=true`
- `CLAUDE_CODE_DISABLE_AGENT_VIEW=1`
- `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`
- `CLAUDE_CODE_DISABLE_CRON=1`
- `CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF=1`
- `CLAUDE_DISABLE_ADOPT=1`
- `disableWorkflows=true`
- `CLAUDE_CODE_DISABLE_WORKFLOWS=1`
- `disableRemoteControl=true`
- `disableDeepLinkRegistration=disable`
- `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS=0`
- `DISABLE_UPDATES=1`

这些控制不会更改 `api.anthropic.com`、OAuth token、请求正文、TLS 或客户端归因。

## 为什么 settings 与启动环境都要设置

普通前台 Claude 是从 `claude-guard` 启动的，环境由 `env -i` 重建。Claude Code 的 background supervisor 和 self-spawn 则可能直接执行原始二进制，不经过 PATH wrapper。

因此关键变量同时存在于：

1. `claude-guard` 注入的前台环境。
2. 官方 profile 的用户级 `settings.json`。

项目级 settings 会在启动前被扫描，不能降低上述保护或注入 base URL、凭据、代理、CA、provider 与 retry watchdog。

## 第三方插件边界

`codex@openai-codex` 当前实现包含 `detached: true` 和 `unref()` 的 broker/background worker。它不改写 Anthropic 流量，但可能在 Claude 终端异常结束后继续运行。

本机安全配置将该插件加入 `blocked_plugins`，并在官方 profile 中关闭。该限制不影响独立 Codex App、Codex CLI 或 CC Switch profile。

## 客户端固定

安全配置可以固定：

- `client_version`
- `client_sha256`
- `client_macos_team_id`

任何一项不一致都会在网络请求和 OAuth 使用之前失败。自动更新也被关闭，版本切换必须先完成离线包、签名和回归测试。

## 验收标准

1. 缺少任一生命周期设置时拒绝启动。
2. 项目 settings 或 CLI 参数无法覆盖官方路径。
3. background/Remote Control 命令无法启动。
4. 客户端版本、哈希与签名匹配。
5. 模拟前台进程退出后，watchdog sidecar 在限定时间内退出。
6. 实机验收时，终端退出后不存在 Claude supervisor、background worker 或到 Anthropic 的残留连接。

实机 PTY 验收：

```bash
python3 scripts/verify-terminal-exit.py
```

必须关闭 PTY master 来模拟真实终端退出。只发送 `SIGHUP` 不是等价测试，因为 Claude Code TUI 可以忽略单独的 `SIGHUP`，而真实终端退出还会断开 PTY。

## 政策边界

本项目是本机安全与可靠性工具，不是风控规避工具。它不清洗水印、不伪造 timezone/locale、不隐藏客户端归因、不转移 OAuth token，也不能保证账号不会受到平台限制。

如果账号已经被限制，应通过 Anthropic 官方申诉或支持渠道处理；使用其他账号绕过封禁不在本项目支持范围内。
